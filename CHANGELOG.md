# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

## [3.0.0] — 2026-10-10

Complete rewrite of the library internals, previously published as `zca-js` (v2.x). The wire protocol is unchanged — the same 155 endpoints talk to the same Zalo services — but everything around them was rebuilt.

### Added

-   **`zalo-client` package name** with `ZaloClient` (login entry point) and `ZaloApi` (endpoint aggregate).
-   **HTTP retry policy** (`retry` option): exponential backoff with full jitter, `Retry-After` support on `429`/`503`, retry on `408/425/429/500/502/503/504` and network failures. Only idempotent methods (`GET`, `HEAD`) retry by default so a message can never be sent twice.
-   **Per-request timeout** (`retry.timeoutMs`, default 60s) via `AbortController`; hung requests fail instead of blocking the process forever.
-   **Leveled logging**: `logging` now accepts `"silent" | "error" | "warn" | "info" | "verbose"` in addition to `true`/`false`, with colored output.
-   **`ZaloError` base class** for the whole error hierarchy (`ZaloApiError`, `ZaloApiMissingImageMetadataGetter`, `ZaloApiLoginQRAborted`, `ZaloApiLoginQRDeclined`).
-   `MIGRATION.md` and `CHANGELOG.md`.

### Changed

-   **Modular core**: the old flat `utils.ts` / `context.ts` / `Errors/` / `zalo.ts` / `apis.ts` files were split into focused modules:
    `core/crypto`, `core/http`, `core/factory`, `core/logger`, `core/errors`, `core/utils`, `core/context`.
-   **`src/apis/` → `src/api/`**, with `src/api/index.ts` generated by `scripts/buildAPI.js`.
-   **Lazy endpoint binding**: endpoints are created on first property access instead of eagerly building ~155 closures on every login. Faster startup, lower memory, and a partially-populated service map only fails if that specific endpoint is used.
-   **Streaming file checksums**: `getMd5LargeFileObject` hashes files chunk-by-chunk from a file handle instead of loading the whole file into memory (constant memory for multi-GB uploads).
-   **HTTP engine rewritten on the Fetch API**: headers are merged through `Headers` (no more mutating caller options), redirects keep the original cookie semantics, and `set-cookie` parsing still uses `getSetCookie()`.
-   **Cookie parsing no longer mutates the caller's cookie array.**
-   Build scripts no longer require Bun (`node scripts/buildAPI.js`, `npm run build`); `test:feat` still uses Bun.
-   `CallbacksMap` TTL timers are `unref()`-ed so pending upload callbacks never keep the process alive.

### Removed

-   **The `zca-js` name and identity**: package, `ZcaApiError` error name (was incorrectly set on `ZaloApiError`), repository metadata.
-   **`crypto-js`** — all hashing/AES now uses built-in `node:crypto` (byte-for-byte compatible with the previous implementation; verified against `zca-js@2.2.0` outputs).
-   **`spark-md5`** — replaced by `node:crypto` incremental hashing.
-   **`semver`** and the automatic npm update check (`src/update.ts`): the library no longer phones the registry on login. The `checkUpdate` option was removed.
-   `src/utils.ts`, `src/context.ts`, `src/zalo.ts`, `src/apis.ts`, `src/Errors/`, `src/update.ts` (replaced by the modules above).

### Fixed

-   `ZaloApiError.name` was `"ZcaApiError"`; it is now `"ZaloApiError"`.
-   Requests could hang forever on a stalled connection (now subject to `retry.timeoutMs`).

### Compatibility

Legacy names remain exported as deprecated aliases: `Zalo` (→ `ZaloClient`), `API` (→ `ZaloApi`). See [MIGRATION.md](./MIGRATION.md) for the full alias table.

## [2.2.0] and earlier

Published as `zca-js`. See the git history of the original repository for earlier changes.
